# Handoff: first-pass layout of the receiver (rx_*), DRC / LVS / antenna / extraction (sim server)

**Goal: a first-pass layout of every receiver block and of `rx_top`, each made by a generator, clean in magic DRC,
KLayout DRC, antenna and LVS against its xschem schematic, then extracted and re-simulated on the few benches that
layout can break. Write it up in `docs/rx_layout.md`.** This is a first pass: find out what the layout costs (area,
parasitics, I/Q phase, noise), not a sign-off. Matt will decide the open review items with these numbers.

**rx_top floorplan (a proposal; improve it and say why):**
- Signal flow in one direction: the RF input at one edge, then LNA, mixers, baseband, limiters, and the q_i / q_q
  outputs at the opposite edge. The I and Q arms as two identical rows, one above the other, with the LO buffers
  between the LNA and the mixers.
- The quiet end (LNA inputs, baseband stage 1, the AC-coupling nodes) as far as possible from the noisy end (the LO
  buffers' edges and the comparators). Put the supply decap between them.
- One VDD and one VSS for the whole receiver, its **own pins**: the review may move the receiver to VAPWR
  (`docs/platform.md`), so don't merge its supply with the VCO's inside the cell.
- Guard rings: an n-well tap ring around each PMOS group, a p+ substrate ring around each block, and a p+ ring
  around the whole receiver.
- Metal4 left free for the TT power stripes; no Metal5 (not available to TT projects).

**Ports of rx_top** (as the schematic): VDD, VSS, inp, inn, ls (the I LO, from lsdiv), aq (the ring's a2, into
rx_lsq), en, q_i, q_q. **Leave these decisions as the schematic has them** (open review items, don't change them):
rx_lo's `qenb` tied to VSS (the Q copy always on), rx_en as a plain port, the two-pole filter, the antenna pins not
assigned.

## Checks (all must pass, judged from the output files and log tails, not exit codes)
Per block and for rx_top, with a `layout/gen/check_rx_<block>.sh` modelled on `check_tx.sh`:
1. **magic DRC 0 errors, KLayout DRC 0 errors** (`feol=true beol=true`, and print which rules ran).
2. **Antenna: 0 violations.** Prove the check on a copy with a deliberate violation once.
3. **LVS against the xschem netlist:** "Circuits match uniquely", **no property errors**. netgen treats the PDK
   resistors as black boxes, so also diff every resistor W / L and every MOS W / L / m against the netlist (as
   `xschem/gen/check.py` does).
4. **Mutation test** each block's LVS with two broken copies of the source (one m, one gate connection); both must
   fail.

## Running unattended
1. **Never end a turn with untracked work running.** Start long jobs with the Bash tool's `run_in_background: true`,
   not `nohup … &`. If something must survive the session, also start a Monitor on a done-marker file.
2. **One driver script** (`layout/gen/rx_layout_driver.sh`) chains every step: blocks → checks → extraction → benches →
   summary. Corners come from a config block at its top. Each step writes `build/rx_layout/status.txt`; the final step
   writes `build/rx_layout/DONE` or `FAILED`.
3. **Fail loudly and early:** each step checks its own outputs (expected files, "Circuits match uniquely", no
   "singular", "Transient op started" present) before the next starts. On failure, stop with the log tail; diagnose
   and retry at most twice, then write up and stop.
4. **Heartbeat:** schedule a wakeup at about 1.5× the estimated step time, at least 20 minutes, at most 60; re-arm it.
5. **Progress where the laptop can see it:** replace the first line of this file with `> Running: step N/M since
   HH:MM, ETA HH:MM` at each step change, commit and push. Send a PushNotification when it finishes or fails, if the
   tool is available.
6. **Finish in one go:** when the driver ends, write up, commit and push without waiting to be asked.
7. **CPU budget:** use `.claude/skills/mixed-signal-asic/scripts/sched.py` or `xargs -P 8` inside the driver.

## Time budget and stop rules
- About 1.5 h per block to a DRC- and LVS-clean GDS. If a block isn't clean by then, write up where it got stuck and
  move on to the next block; rx_top waits for all of them.
- If the extracted I/Q phase leaves 72 ± 25°, stop the bench step and report: it means rx_lsq is not a faithful
  copy of lsdiv's level shifter.

## Traps (from this project)
- **No MIM on TT GF.** Large caps are MOS caps; check every MOS cap's DC bias puts it in inversion (`docs/learning.md`,
  section 11). The AC-coupling caps are PMOS with the **gate** on the high-Z node: keep it that way (an NMOS version
  leaked through its junctions and biased the next stage off, `docs/rx_design.md`).
- **magic 8.3.642** for extraction (8.3.684 drops substrate C). **KLayout gf180 DRC needs `feol=true beol=true`**, or
  it silently runs zero rules.
- **magic `rc` extraction double-counts coupling C** on ports and split nets: always use `rcfix.py`'s output.
- `tools/osic-mac` doesn't pass env vars into Docker: use `tools/osic-mac env K=V cmd`.
- The GF180 models give one mismatch draw per instance, ignoring `m`: if you add a Monte Carlo run, split devices
  into unit instances.
- Frequency in the ring is measured at **mid-swing** (it swings vg…VDD).
- `rm` is aliased to `rm -i`: use `command rm -f`. Kill ngspice runs with `[x]`-bracketed `pkill -f` patterns.
